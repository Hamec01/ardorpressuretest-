## 1. Что сейчас (проверено 06.10.2026)

### 1.1 Сайт открыт всем
- В вебе нет экрана входа: `App` рендерится гостю целиком ([main.tsx](../apps/web/src/main.tsx)).
- API, проверено по AST всех маршрутов, без авторизации отдаёт:

| Что | Маршруты |
|---|---|
| Логи, поиск, корзина | `GET /tests`, `GET /tests/{log_no}`, `GET /tests/trash`, `GET /tests/ptr-source-identifiers`, `POST /tests/resolve-ptr-sources` |
| Файлы и ZIP | `GET /tests/artifacts/{id}/file`, `GET /tests/{log_no}/revisions/{id}/zip` |
| Протоколы PTR и их PDF | `GET /records`, `GET /records/{id}`, `/pdf`, `/full-pdf`, `/estimate-pages`, `GET /records/verify/{code}` |
| Планы опрессовки | `GET /planned-tests/lists`, `GET /planned-tests/lists/{id}/pipes` |
| **Изменения без входа** | `POST /process`, `POST /process/package` (загрузка новых логов), `PUT /tests/{log_no}/revisions/{id}/metadata` (правка метаданных, переименование Log No.) |
| Синхронизация Windows-клиента | `POST /sync/*`: открыто намеренно до выпуска нового desktop-клиента (ADR-010 §12) |

- Viewer может менять данные: `PATCH /tests/{log_no}/pipecloud` и `POST /tests/{log_no}/photos` требуют только «любой вход» (`require_authenticated_user`). По ADR-005 §3 это действия Admin/Foreman.
- API-порт `:8000` доступен снаружи напрямую, в обход nginx (`http://84.247.130.242:8000/health` → 200).

### 1.2 Публичная ссылка = номер лога
`/share/{log_no}` открывает `PublicLogView`, который читает **внутренний** API по номеру лога. Номера идут подряд (`066FED`, `067FED`…), поэтому, перебирая адрес, можно открыть **любой** лог. Даже если закрыть основной сайт, такая ссылка не изолирует ничего. ADR-005 §10 требует случайный токен, хранение только hash в БД, отдельный публичный DTO, проверку каждого файла на принадлежность публикации и отзыв ссылки.

### 1.3 Аккаунты
- В API только `GET /auth/users` (admin). Создания, смены роли, деактивации и сброса пароля нет ни в API, ни в интерфейсе.
- Поле `users.must_change_password` и flow смены пароля уже есть (R3), но выставить флаг сейчас некому.
- На staging активны только 2 аккаунта, оба `admin`. Foreman и прежний `operator` деактивированы. Завести сотрудника сейчас нельзя.

### 1.4 Что уже готово и переиспользуется
- `require_role()` уже fail-closed (без fallback-пользователя), CSRF применяется ко всем unsafe-запросам ([auth.py:600](../services/api/auth.py#L600)).
- Cookie-сессии R3 работают на HTTPS-адресе `https://84-247-130-242.sslip.io` (Caddy → `:8080`).
- `/docs` и `/openapi.json` в server mode отключены (404). Service worker нет. Физическое удаление уже отключено.

## 2. Цель

1. **Сайт закрыт.** Без входа открывается только страница входа. Все business API отвечают 401 без сессии и 403 при недостаточной роли.
2. **Share-ссылки работают без входа**, но открывают ровно один опубликованный лог. Ссылку можно отозвать.
3. **Admin управляет аккаунтами:** создать, сменить роль, деактивировать или вернуть, сбросить пароль. Новый сотрудник при первом входе меняет временный пароль.

## 3. Этапы

### Этап 1 — Аккаунты (R7, backend + UI). Аддитивно, ничего не ломает

**API** (только `admin`, CSRF, аудит в одной транзакции с изменением, ADR-005 §11):

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/v1/auth/users` | уже есть; расширить ответ: `role`, `is_active`, `must_change_password`, `created_at`, `last_login_at`, число активных сессий |
| `POST` | `/api/v1/auth/users` | `{username, full_name, email?, role, password?}`: галочка «Задать пароль вручную» → admin вводит пароль сам; без галочки система создаёт **ссылку для установки пароля** |
| `PATCH` | `/api/v1/auth/users/{id}` | `{full_name?, email?, role?, is_active?}`; смена роли или деактивация **отзывают все сессии** аккаунта |
| `POST` | `/api/v1/auth/users/{id}/password-link` | новая ссылка для установки или смены пароля (кнопка «Отправить ссылку» в профиле); прежние неиспользованные ссылки этого аккаунта отзываются |
| `PUT` | `/api/v1/auth/users/{id}/password` | admin задаёт пароль вручную; отзыв всех сессий |
| `GET` | `/api/v1/auth/password-links/{token}` | **без входа**: проверить ссылку, вернуть имя и логин |
| `POST` | `/api/v1/auth/password-links/{token}` | **без входа**: `{new_password}` → пароль установлен, ссылка погашена, все прежние сессии отозваны, переход на вход |

Правила:
- `username`: `^[a-z0-9._-]{3,32}$`, приводится к нижнему регистру, уникален. `role ∈ {admin, foreman, viewer}`.
- **Удаления аккаунта нет**, только деактивация: физическое удаление запрещено (ADR-005 §4, §12).
- **Last-admin guard:** нельзя понизить или деактивировать последнего активного admin. Проверка TOCTOU-safe: в одной транзакции блокировка строк активных admin (`SELECT … FOR UPDATE`) или advisory lock (ADR-005 §8, ADR-010 §12).
- Admin не может деактивировать сам себя и снять с себя роль admin (защита от самоблокировки).
- **Ссылка для пароля** (новая таблица `password_links`, additive-миграция): `id`, `user_id`, `token_hash` (SHA-256, unique), `purpose` (`invite`/`reset`), `created_by_user_id`, `created_at`, `expires_at` (72 часа), `used_at`, `revoked_at`. Токен — 32 случайных байта (`secrets`), в БД только hash, одноразовая, отдельный rate limit на проверку. Адрес: `https://ardor.collabstudio.run/set-password/<token>`.
- Пароль, заданный admin вручную, проверяется по тем же правилам (6–128 символов, ADR-010 §3). Галочка «Попросить сменить при первом входе» включена по умолчанию → `must_change_password=true`.
- Пароли и токены ссылок не попадают в логи и аудит.
- Legacy-роли `operator`/`manager` показываются как «устаревшая роль». При редактировании admin обязан выбрать одну из трёх (ADR-005 §2).

**UI:** раздел **«Аккаунты»** только для admin (вкладка на десктопе, пункт в «Ещё» на телефоне):
- список: имя, логин, роль (бейдж), статус, последний вход;
- видны **все** профили, включая деактивированные (фильтр «Активные / Все»);
- «Создать аккаунт» → окно: имя, логин, роль, галочка «Задать пароль вручную». Без галочки после создания показывается ссылка для установки пароля с кнопкой «Скопировать», её можно переслать сотруднику в чат;
- в профиле: изменить имя или роль, деактивировать или активировать (с подтверждением), **«Отправить ссылку для смены пароля»** (новая ссылка, если пароль утерян), «Задать пароль вручную»;
- у каждого профиля статус ссылки: «ожидает установки пароля до …», «использована», «нет»;
- три языка, мобильная вёрстка по нормам аудита (44 px, без обрезки).

Файлы: новый `routes/accounts.py`, `models.py` (`PasswordLink`), `auth_operations.py`, `schemas.py`, миграция `password_links`; `apps/web/src/components/AccountsTab.tsx` и `SetPasswordPage.tsx` (новые), `main.tsx`, `App.tsx`, `MobileNavigation.tsx`, `Header.tsx`, `api.ts`, `types.ts`, `i18n.ts`.

### Этап 2 — Share-ссылки по токену (R5). Аддитивно, старые ссылки продолжают работать

**Модель `public_shares`** (additive Alembic-миграция):

| Поле | Назначение |
|---|---|
| `id` UUID | стабильный ID публикации |
| `token_hash` | SHA-256 токена, unique; сам токен в БД не хранится |
| `resource_type` | `log` (PTR и план — позже, см. решение 4) |
| `pressure_test_id` FK | стабильный ID лога, **не** `log_no` (переименование лога ссылку не ломает) |
| `created_by_user_id`, `created_at` | из сессии |
| `revoked_at`, `revoked_by_user_id` | отзыв |
| `last_accessed_at`, `access_count` | видно, открывали ли ссылку |

**Токен:** `HMAC-SHA256(ARDOR_SHARE_SECRET, share.id)` в base64url (43 символа, 256 бит). В БД лежит только `SHA-256(token)`, как требует ADR-005 §10. Сервер может заново вычислить ссылку по `id`, поэтому кнопка «Скопировать ссылку» работает повторно и не плодит новые публикации. Ротация `ARDOR_SHARE_SECRET` разом аннулирует все ссылки (аварийный рубильник).

**API:**

| Метод | Путь | Доступ |
|---|---|---|
| `POST` | `/api/v1/shares` `{resource_type: "log", log_no}` | admin/foreman; если активная ссылка на этот лог уже есть, возвращает её |
| `GET` | `/api/v1/shares?log_no=` | admin/foreman: активные ссылки лога |
| `DELETE` | `/api/v1/shares/{id}` | admin/foreman: отзыв (логический, с аудитом) |
| `GET` | `/api/v1/public/shares/{token}` | **без входа**: отдельный `PublicLogDTO` с явным списком полей |
| `GET` | `/api/v1/public/shares/{token}/artifacts/{artifact_id}` | **без входа**: файл, только если он принадлежит **текущей основной ревизии** опубликованного лога |
| `GET` | `/api/v1/public/shares/{token}/zip` | **без входа**: ZIP текущей основной ревизии |

- Режим LIVE (ADR-005 §7): гость видит актуальную основную ревизию. Отозванная ссылка, неизвестный токен и чужой `artifact_id` дают одинаковый 404, без подсказок.
- Ответы публичных маршрутов: `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex`.
- Публичный DTO не содержит внутренних ID пользователей, аудита, ревизий-черновиков и корзины.

**Старые ссылки `/share/{log_no}` продолжают работать** (решение владельца, заменяет ADR-005 §7.5):
- миграция создаёт для **каждого лога, существующего на момент выкатки**, публикацию с флагом `legacy_log_no_access=true`, автор `system`;
- `GET /api/v1/public/legacy/{log_no}` работает только для лога с активной legacy-публикацией. Он возвращает тот же `PublicLogDTO`, и дальше всё идёт через токен этой публикации;
- **новые логи** по номеру не открываются: только по `/s/{token}`. Перебор номеров новых логов ничего не даёт;
- admin/foreman может отозвать legacy-доступ у конкретного лога. Общий выключатель `ARDOR_LEGACY_SHARE_LINKS=off` закрывает все старые ссылки сразу, когда команда перейдёт на новые;
- честное ограничение: старые логи (созданные до выкатки) остаются доступными по номеру, как сегодня, пока не отозваны. Это не хуже текущего состояния, а новые логи защищены.

**Веб:**
- новый маршрут `/s/{token}` → `PublicLogView` на публичном API; гость видит **полный лог** — данные, график, фото, все файлы ревизии (PDF, XLSX, CSV, TXT, PNG) со скачиванием и ZIP;
- `/share/{log_no}` → тот же `PublicLogView` через legacy-endpoint;
- кнопка «Ссылка на лог» (карточка и окно лога, только admin/foreman) → `POST /shares` → копирует URL; в окне лога показано «Публичная ссылка активна · Отозвать».

Файлы: `services/api/models.py`, новый `routes/shares.py`, `schemas.py`, `config.py` (`ARDOR_SHARE_SECRET`, обязателен в server mode), `main.py`, миграция; `main.tsx`, `PublicLogView.tsx`, `shareLinks.ts`, `api.ts`, `TestCard.tsx`, `TestDetailModal.tsx`, `i18n.ts`.

### Этап 3 — Экран входа (R6) и закрытие API (R4). Здесь сайт закрывается

**Веб (AuthGate):**
- `main.tsx`: `/s/{token}`, `/share/{log_no}` (legacy) и `/set-password/{token}` рендерятся без входа. Всё остальное идёт через `AuthGate`.
- `AuthGate`: загрузка → `GET /auth/me`. 401 → **полноэкранная страница входа**: логотип, логин, пароль, язык FI/EN/RU, тема; 429 → «Слишком много попыток, повторите через N мин»; подпись «Нет аккаунта? Обратитесь к администратору».
- `must_change_password` → блокирующий экран смены пароля (переиспользуется `ChangePasswordModal`).
- Истёкшая сессия посреди работы (401 из `authFetch`) → снова экран входа, без потери вкладки.
- Удаляются гостевые ветки: кнопка «Войти» в шапке и в «Ещё», переход «+ → вход». Проверки `canEdit` для Viewer остаются.

**API (fail-closed):** новый `services/api/permissions.py` с двумя зависимостями:
- `require_reader` = `require_role(["admin", "foreman", "viewer"])`: все business-GET из таблицы 1.1, `POST /tests/resolve-ptr-sources`, `GET /records/verify/{code}` (ADR-005 §7.8: verify-код не даёт публичного доступа);
- `require_writer` = `require_role(["admin", "foreman"])`: `POST /process`, `POST /process/package`, `PUT …/metadata`, `PATCH …/pipecloud`, `POST …/photos`.

Публичными остаются только `POST /auth/login`, `POST /desktop/login`, `POST /desktop/token/refresh`, `GET /health`, `/api/v1/public/*` и `/api/v1/auth/password-links/*`. **`/sync/*` закрывается** (`require_writer`): Windows-клиент со входом уже у всех (решение 6).

**Регрессионный «замок»:** тест перебирает `app.routes` и падает, если у любого маршрута вне явного allowlist нет auth-зависимости. Новый открытый маршрут не пройдёт CI незаметно.

### Этап 0 — Домен `ardor.collabstudio.run` (можно сделать сразу, ничего не ломает)
Проверено 06.10: домен `collabstudio.run` (DNS в Vercel) указывает на этот сервер, на поддомены стоит wildcard на серверы Vercel, поэтому `ardor.collabstudio.run` сейчас уходит в Vercel.
1. **Вы:** в Vercel → Domains → `collabstudio.run` → DNS → добавить запись `A  ardor  84.247.130.242` (явная запись приоритетнее wildcard).
2. **Вы (одна команда sudo, текст подготовлю):** блок в `/etc/caddy/Caddyfile` `ardor.collabstudio.run { reverse_proxy 127.0.0.1:8080 … }` и `caddy reload`. Caddy сам выпустит сертификат Let's Encrypt.
3. Конфликта с collabstudio.run нет: отдельный хост, отдельный сертификат, cookie ARDOR — `__Host-` (только для своего хоста); collabstudio.run не ставит cookie на весь домен (проверено).
4. После проверки HTTPS: `ARDOR_PUBLIC_ORIGIN=https://ardor.collabstudio.run`, новые share-ссылки и ссылки для пароля строятся на этом адресе.

## 4. Порядок выкатки

Каждый шаг: бэкап (`/home/deploy/ops/ardor-pressure-test/backup-ardor.sh`) → тег отката образа (`before-…`) → выкатка → проверка → запись в отчёт.

5. **Инфраструктура (этап 4).**

**Откат:** веб и API откатываются тегами образов за минуту. Миграция `public_shares` аддитивная, на откат API не влияет и не downgrade-ится (ADR-010 §11).

## 5. Проверка (Definition of Done)

**Backend (pytest):**
- матрица маршрутов: каждый business-маршрут без сессии даёт 401, Viewer на изменения получает 403;
- share: неизвестный, отозванный токен и чужой `artifact_id` → 404; Viewer не может создать ссылку; файл черновой ревизии не отдаётся; переименование лога ссылку не ломает; в БД нет исходного токена;
- legacy: старый `/share/{log_no}` открывает существующий лог; новый лог по номеру → 404; отзыв legacy и `ARDOR_LEGACY_SHARE_LINKS=off` закрывают доступ;
- ссылки для пароля: одноразовость, истечение через 72 часа, новая ссылка отзывает прежнюю, после установки пароля сессии отозваны;
- аккаунты: создание с `must_change_password`; временный пароль не попадает в аудит; деактивация и сброс отзывают сессии; last-admin guard, включая два конкурентных запроса на throwaway PostgreSQL; нельзя деактивировать себя.

**Web:** `tsc`, `vite build`, тесты исходников в стиле `test_mobile_ux_audit_fixes.py`.

**E2E (Playwright, staging):**
- гость на `/` видит только вход, прямые API-запросы → 401;
- share-ссылка открывается в чистом браузере без входа, после отзыва → «ссылка недействительна»;
- admin создаёт Viewer → вход Viewer → обязательная смена пароля → только чтение;
- мобильный аудит экрана входа и раздела «Аккаунты» (320/390 px, три языка).

| 6 | Windows-клиент | Новая версия со входом у всех → `/sync/*` закрывается в этом релизе |

## 7. Что не входит
- Справочник манометров (часть R7 в ADR-005): отдельный этап.
- Восстановление пароля по email: сбрасывает только admin (PRD §18).
- WireGuard, отдельный хостинг и домен: только как вариант в решении 1.
